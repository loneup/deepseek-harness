Nexus 与 DeepSeek Harness 兼容层迁移实施方案
一、文档目标
本方案用于将 Nexus Bridge 与 DeepSeek Harness 之间的直接耦合改造成稳定的兼容适配层。
目标结构：
Nexus v4 HTTP/SSE 协议
    ↓
nexus-bridge
    ↓
NexusDshPort 稳定接口
    ↓
nexus-dsh-compat 兼容层
    ↓
DeepSeek Harness 0.1.3-alpha.1 或未来版本
完成后，nexus-bridge 不再直接依赖 DeepSeek Harness 的具体 API、错误类型、事件类型或内部品牌类型。
未来 DeepSeek Harness 普通 API 变化时，主要修改 nexus-dsh-compat，不再大范围修改 nexus-bridge、ui-settings-nexus 和 iOS 客户端。

七、阶段 S2：实现 dsh 0.1.3-alpha.1 适配器
新增：
packages/host/nexus-dsh-compat/src/dsh-013-adapter.ts
适配器类：
Dsh013Adapter implements NexusDshPort
当前 dsh API 的准确调用方式：
ctx.sessionController.list({}, signal)
ctx.sessionController.create(request)
ctx.sessionController.modelCatalog()
ctx.sessionController.selectModel(request)
ctx.sessionController.prompt(request, signal)
ctx.sessionController.cancel(request)
ctx.sessionController.page(request, signal)
ctx.subagents.remoteExportList(parentSessionId, signal)
ctx.subagents.prompt(request, signal)
ctx.subagents.interruptByParent(childSessionId, parentSessionId, 'continuable')
必须遵守：
1. modelCatalog 无参数。
2. create 当前不接 signal。
3. selectModel 当前不接 signal。
4. cancel 当前不接 signal。
5. list、page、prompt 接收 signal。
6. prompt 必须传 branded requestId。
7. page 返回 records，不是 events。
8. SessionAddress 只能在适配器内部构造。
9. Subagent list 必须调用 remoteExportList，不能通过普通 Session 列表过滤伪造。
普通 prompt 的内部转换：
ctx.sessionController.prompt({
  requestId: request.requestId as SessionRequestId,
  sessionId: request.sessionId as SessionId,
  mode: request.mode,
  content: mapPromptContent(request.content)
}, signal)
普通 history 的内部转换：
ctx.sessionController.page({
  address: {
    kind: 'session',
    sessionId: request.sessionId as SessionId
  },
  throughSeq: -1,
  beforeSeq: request.beforeSeq,
  maxMessages: request.maxMessages
}, signal)
Subagent history 的内部转换：
ctx.sessionController.page({
  address: {
    kind: 'subagent',
    parentSessionId: request.parentSessionId as SessionId,
    childSessionId: request.childSessionId as SessionId,
    mode: request.mode
  },
  throughSeq: -1,
  beforeSeq: request.beforeSeq,
  maxMessages: request.maxMessages
}, signal)

八、阶段 S3：集中错误和事件映射
新增：
packages/host/nexus-dsh-compat/src/errors.ts
packages/host/nexus-dsh-compat/src/events.ts
错误识别必须使用：
remoteErrorOf(error)
不得只使用 instanceof RemoteError。
建议错误映射：
session/not-found 映射为 unknown_session。
gateway/bad-request 映射为 malformed。
gateway/cancelled 映射为 host_cancelled。
subagent/not-found 映射为 unknown_subagent。
subagent/unauthorized 映射为 subagent_unauthorized。
未知错误映射为 host_error。
错误消息必须脱敏，不向 Nexus 客户端泄露 dsh 内部堆栈和敏感路径。
事件映射：
turn/start 映射为 turn.started。
assistant/chunk 的 text-delta 映射为 message.delta。
非文本 assistant chunk 忽略。
assistant/message 映射为 message.committed。
turn/end completed 映射为 turn.completed。
turn/end aborted、interrupted、disposed 映射为 turn.cancelled。
turn/end error 映射为 turn.failed。
approval/decided 映射为 approval.resolved。
tool/call 映射为 tool.started。
tool/result 映射为 tool.result。
未知事件返回 undefined。
未知事件不得推进 Nexus sequence。

十一、阶段 S6：历史、实时事件和审批
session.open 流程必须保持：
读取历史
    ↓
发送历史种子
    ↓
发送 session.subscribed anchor
    ↓
订阅实时事件
Bridge 当前建议继续使用：
ctx.on('session/event')
不要在本次迁移中同时使用：
ctx.on('session/event')
ctx.sessionController.follow()
否则可能重复发送事件。
follow 可以作为未来独立重构，不应在本次迁移中与现有广播并行接入。
内部回看事件时使用：
session.snapshotEvents()
不要使用：
session.events
审批继续使用：
ctx.on('approval/request', ...)
并且 waterfall listener 必须调用 next()。

十五、阶段 S10：未来版本兼容矩阵
建议记录：

以下变化通常只需要修改兼容适配器：
1. dsh 方法重命名。
2. 参数字段变化。
3. signal 参数变化。
4. branded ID 变化。
5. records 或 events 字段变化。
6. RemoteError 错误码变化。
7. SessionAddress 变化。
8. Subagent API 重组。
9. dsh 事件内部字段变化。
10. dsh 包名变化。
以下变化不能保证只修改适配器：
1. dsh 删除实时事件能力。
2. dsh 删除历史读取能力。
3. dsh 删除 Subagent 能力。
4. dsh 修改 Session 持久化格式。
5. dsh 改变事件的根本语义。
6. Nexus v4 协议改变。
7. sequence 语义改变。
8. iOS 依赖字段改变。
