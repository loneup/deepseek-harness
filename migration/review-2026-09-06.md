### B.1 preview-boot e2e 修复（接手第一件事）

**前任留下的困惑**：已把 `|NEXUS_ENV is not set` 加进两处 console 断言正则，Node 单测正则可匹配，但 vitest 仍失败于 418 行 `consoleErrors.filter(...) 期望 [] 实得 [nexus-bridge] NEXUS_ENV is not set ...`。

**根因**：该文件两处断言的过滤方向相反——
- `bootPreview`（418 行）：`consoleErrors.filter(line => /.../.test(line))` 期望 `[]` —— **正向匹配的失败允许清单**：只有命中正则的行才算失败。把豁免模式加进正则 = 命中 = 保留进断言结果 = 失败。前任的"正则明明应命中"恰恰说反了：**命中即失败**。
- `bootEmptyPreview`（479 行）：`filter(line => !line.includes(...) && ...)` —— 排除法，加 `!line.includes('NEXUS_ENV is not set')` 是**正确**的（前任这处改对了，保留）。

**修复**：418 行正则回退到原始形态（原始正则本来就不含该模式 → 不命中 → 天然豁免；bridge 的警告本身保留，源头在 `packages/host/nexus-bridge/src/index.ts:132`，preview worker 走 legacy 未配置路径启动时必然打印，属预期），并加注释说明该正则是 failure allowlist、豁免靠"不匹配"实现。

**验证**：单文件 1/1 通过（7.5s）；全量 `test:web:built` **exit 0，93 文件通过/1 跳过，317/332 通过、15 跳过、0 失败**（423s）。

### B.3 CPython 甄别（根因修正：不是缺安装）

- **CPython 3.14.7 早已装好**（homebrew `python@3.14`）。244 项失败真因是 **PATH 顺序**：`/usr/bin/python3`(3.9.6) 排在 `/opt/homebrew/bin/python3`(3.14.7) 之前（交互 shell 与会话 shell 皆然），`resolvePythonBin` 按 PATH 解析到 3.9.6，低于包内 `MIN_CPYTHON=3.10` 硬性探针。
- **会话内修复**：外科 PATH——`/tmp/py314-bin` 只放 python3 符号链接后前置（node 仍解析 22.23.1）。
- 结果：code-runtime-python 套件 **283 通过/2 跳过/0 失败**；全量 `pnpm run test` **18328 通过 / 1 失败 / 118 跳过**（基线 18050 通过/245 失败 → **244 项 Python 失败全部消除**）。唯一失败 = KNOWN_ISSUES #10 已记录的 spill-local 边界计时 flake，隔离复跑 41/41 通过，与迁移无关。
